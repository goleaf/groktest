# ADR 0002 — UUIDv7 identifiers

## Context

Records must be created offline. IDs cannot come from a server. Sequential IDs leak volume and are guessable.

## Decision

UUIDv7 strings (128-bit, time-ordered, RFC 9562). Implemented with `crypto.getRandomValues` in-repo. No `uuid` package.

## Alternatives

- ULID: similar, less standard in 2026
- UUIDv4: not time-ordered, worse as a default sort
- Nanoid: shorter but custom

## Consequences

IDs sort roughly by creation time. They work as primary keys in IndexedDB and future SQL. Slightly longer than ULID in UI; we do not display raw IDs to users.
